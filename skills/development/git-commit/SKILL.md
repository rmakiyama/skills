# Git Commit

コミットを作る前に、差分を論理的な単位に分割してから記録する。

## 原則

- 1コミット = 1つの論理的変更
  - 複数の意図が混在する差分は、複数のコミットに分割する
- フォーマット変更とロジック変更は別コミットにする
  - 差分の本質が読みにくくなり、レビューコストが上がるため
- 秘密情報・ビルド生成物を含めない
  - ステージする前に差分の中身を確認する
- ステージする対象は絞る
  - `git add -A` や `git add .` は使わず、`git add <file>` や `git add -p` で意図した範囲だけを含める

## コミットメッセージ

- 1行目: 変更の要約
- 本文(必要な場合): なぜその変更が必要だったか。背景・制約・トレードオフなど
- WhatよりWhyを書く
  - Whatはdiffで分かる。差分を言い換えただけの説明は書かない
- メタ的な説明はしない
  - コミットは作業報告ではない。指摘の出所、修正の回数、作業の実況(「〜に対応」)、成果の自己申告(「保守性が向上」)は書かない
  - 悪い例: 「Gemini Code Assistのレビュー指摘に対応。値が初期化時に決定するvalプロパティにget()は不要なため」
  - 良い例: 「値が初期化時に決定するvalプロパティにはget()は不要なため直接初期化に変更」
